# A 股分析 Agent 全栈自建指南

基于 Python 全栈自建路径，使用 LangGraph 编排多 Agent 工作流，Tushare + AKShare 获取 A 股数据，Streamlit 提供可视化交互界面。

## 一、整体架构

采用**四 Agent 协作模式**，各 Agent 独立运行、交叉校验：

| Agent | 职责 |
|---|---|
| **数据采集 Agent** | 定时获取行情、财报、新闻等多源数据，完成清洗与标准化，确保数据可追溯 |
| **行情分析 Agent** | 基于技术指标完成形态与趋势判断，输出结构化技术分析报告 |
| **策略决策 Agent** | 综合技术面、基本面、情绪面、资金面进行交叉比对，给出参考结论与置信度标注 |
| **报告推送 Agent** | 将分析结果格式化为可读报告，通过 Streamlit 仪表盘展示 |

> 这套架构不含"自动下单 Agent"——个人炒股 Agent 的核心价值在分析辅助，手工执行交易。至少用一个完整季度的实盘数据验证 Agent 建议质量后，再考虑是否接入执行层。

**数据流**：

```
Tushare（财报/估值）──┐
                      ├──→ 数据采集 Agent ──→ 行情分析 Agent ──→ 策略决策 Agent ──→ 报告推送 Agent ──→ Streamlit
AKShare（行情/舆情）──┘
```

## 二、数据层

### Tushare：Phase 1 唯一数据源

- **定位**：覆盖 Phase 1 全部三维数据需求（日线行情、财务基本面、资金流向）
- **核心接口**：`stock_basic`、`daily`、`daily_basic`、`fina_indicator`、`income`、`balancesheet`、`cashflow`、`moneyflow`、`moneyflow_hsgt`
- **认证**：需要 [Tushare Token](https://tushare.pro/register)，实时数据需积分兑换
- **项目内已有**：完整的 Skill 定义与接口文档，见 `.agents/skills/tushare/`

### AKShare：Phase 2 引入

- **定位**：舆情数据 / 市场情绪数据源，Phase 2 加情绪面维度时一起引入
- **核心能力**：800+ API 接口，覆盖舆情和市场情绪数据
- **扩展设计**：数据采集 Agent 通过统一 adapter 接口对接数据源，加 AKShare 只需新增一个 adapter

### 数据可追溯性原则

每一条被下游 Agent 使用的数据都必须标注：**数据来源、获取时间、原始值**。当行情分析 Agent 基于某条数据做出判断而该数据事后被验证有误时，可追溯性是追溯错误源头的唯一手段。

## 三、模型层与 Agent 编排

### LangGraph：Agent 编排框架

LangGraph 已在项目中安装（v1.2.2），用于搭建多 Agent 工作流：

- 每个 Agent 作为独立的 Graph Node，通过 State 传递数据
- 支持条件分支、循环、人工确认节点（Human-in-the-loop）
- 支持持久化 checkpoint，实现长时间运行的 Agent 任务中断与恢复

### LLM 推荐

| 选项 | 优势 | 适合场景 |
|---|---|---|
| **DeepSeek**（推荐） | 国产 API、成本低、中文能力强 | 日常分析、性价比优先 |
| **Qwen（通义千问）** | 国产 API、阿里云生态、中文金融理解强 | 阿里云用户、多模态需求 |
| **本地 DeepSeek / Llama** | 数据不出本机、无 API 费用 | 隐私敏感、长期成本控制 |

### Prompt 结构化：五维度约束

炒股 Agent 的 Prompt 不要写"帮我分析这只股票"——太模糊。一个合格的金融 Agent Prompt，必须在五个维度上被精确约束：

1. **分析维度指定**：要求从技术面（趋势、动量、波动率）、基本面（营收增速、利润率、现金流质量、估值分位）、情绪面（舆情热度、机构动向）、资金面（主力流向、成交量异常）四个维度逐项分析，不得跳过
2. **输出格式锁定**：必须包含趋势判断、核心驱动因素、风险提示和置信度标注，每一项固定位置
3. **推理边界限制**：明确声明"仅基于以下提供的数据进行分析，不要编造未提供的信息，数据不足时标注'该维度数据不足'"
4. **置信度标注要求**：每项结论标注"确定性数据支撑"还是"推测性判断"
5. **冲突识别要求**：当不同维度结论矛盾时（如技术面偏乐观但资金面偏谨慎），要求主动标注矛盾

### Prompt 对比示例

**坏的 Prompt**：

> "帮我分析一下贵州茅台，告诉我该不该买。"

→ Agent 无从下手，可能编造"最新财报"，给出通顺但无法追溯的泛泛回答。

**好的 Prompt**：

> "请基于以下提供的贵州茅台过去 60 个交易日 K 线数据（附件一）和最近一期财报核心指标（附件二），从四个维度逐一分析：
>
> - **技术面**（趋势、均线、MACD 背离信号）
> - **基本面**（营收同比增速、净利润率、ROE、当前 PE 与五年历史分位对比）
> - **资金面**（主力净流入/流出趋势、成交量异常交易日标注）
> - **情绪面**（近期新闻标题中的正面/负面信号统计）
>
> 对每个维度标注置信度（确定性数据支撑/推测性判断），并汇总不同维度间是否存在矛盾信号。如果某维度数据不足，请明确标注'该维度数据不足'并说明缺少哪类数据。"

→ 每个要素都在约束 Agent 行为——工作数据、输出框架、确定性与推测性的区分、冲突处理。

### 幻觉防控工程手段

金融场景对数据幻觉的容忍度极低。Agent 说"该公司最近一期财报营收增长 18%"时，多数个人投资者不会去证监会官网验证。这就是金融 Agent 幻觉的独特危险——不仅给出错误结论，还制造出"已被验证过"的虚假确定感。

约束手段（在搭建初期就应嵌入）：

- 强制要求为每一个可验证事实标注**数据来源和获取时间**
- Prompt 中加入：**"无法确认的数据请标注'该数据未确认'，不要推测填充"**
- 关键数据点（营收、利润、现金流）采用**多源交叉验证**——同时从 Tushare 和 AKShare 获取同一项数据，不一致则标记异常

## 四、交互层：Streamlit 仪表盘

Streamlit 作为分析报告的可视化展示层，提供 Web 界面交互。

### 定位

- Agent 分析结果的主要展示入口
- 替代"报告推送到手机/邮箱"的纯文本模式，提供更直观的数据可视化
- Phase 1 聚焦于**查看**，不涉及交互式操作

### 预期功能

- 股票/指数搜索与行情展示（K 线图、成交量）
- 多维度分析报告展示（技术面、基本面、资金面、情绪面）
- 历史分析报告对比
- 关键指标仪表盘（PE/PB 分位、资金流向、板块强弱排行）

### 安装

```bash
pip install streamlit
```

## 五、风险控制

### 过拟合陷阱

Agent 在历史数据上表现好，不代表未来有效。金融市场的规律是流动的——牛市中验证有效的策略，在震荡市中可能持续亏损。必须在不同市场环境中分段验证策略稳定性。建议设置至少 3 个月的实盘模拟期，用模拟盘或极小仓位持续验证。

### 数据幻觉

大模型在数据缺失时会"编造"信息——引用不存在的财报数据，或将过时新闻错误关联到当前时间点。这是一个工程约束问题，不是"等模型更强就好了"的技术乐观问题。Agent 的每一条数据结论都应标注来源和获取时间，关键数据点需可被重新抓取验证。

### 心理依赖陷阱

当 Agent 持续输出有效分析后，会自然产生危险惯性：不再独立思考。应对手段：

- 要求 Agent 对每项结论标注置信度和信息来源，始终看到不确定性
- 定期在自己独立复盘完成分析前**禁止查看 Agent 输出**，用盲测对比持续检验
- 在日报中加入"反向风险因素"——要求输出一条最不支持自己结论的反面信息

## 六、启动路线图

### 第 1 周：数据层搭建

- 安装 pandas-ta、streamlit，补充 `pyproject.toml` 依赖
- 实现数据采集 Agent：Tushare API → Pydantic 校验 → Parquet 落盘
- 验证能正确获取至少 3 只熟悉股票的日 K 线（至少过去一年）、财务指标、资金流数据

**验收标准**：数据采集连续 5 天无报错，手工随机抽查 20 个数据点与 Tushare 网页端交叉验证

### 第 2-3 周：行情分析 + 策略决策 Agent

- 实现行情分析 Agent：pandas-ta 算指标 → 三维评分（技术面/基本面/资金面） → 结构化 JSON
- 实现策略决策 Agent：结构化结论 → LLM 综合推理 → JSON 输出
- 配置 LLM（DeepSeek 或 Qwen）

**验收标准**：选取一段历史时期做回测，三维评分结果合理，LLM 综合研判能正确识别维度冲突

### 第 4 周+：全链路 + Streamlit 仪表盘

- 四个 Agent 全部跑通：数据采集 → 行情分析 → 策略决策 → 报告推送
- 搭建 Streamlit 仪表盘：输入股票代码 → 查看完整分析报告
- JSON 存 Parquet，支持历史报告对比

**验收标准**：完整闭环运行，选择 2-3 只熟悉股票连续分析，对比"Agent 是否发现了你遗漏的信息"

### 阶段切换原则

- 不以"觉得 Agent 很靠谱"为依据切换阶段
- 每个阶段的验收指标必须全部达标、连续验证期完整通过后，才进入下一阶段
- **过早扩大规模是个人金融 Agent 项目中最常见的失败模式**
