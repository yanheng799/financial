# A 股分析 Agent 系统设计决策记录

> 本文档记录系统设计阶段的关键决策，作为实施的约束条件和验收依据。

## 决策总览

| # | 决策点 | 结论 | 理由 |
|---|---|---|---|
| 1 | 用户规模 | 单人工具 | 无需用户系统、权限控制、并发处理，架构最简 |
| 2 | 数据存储 | Parquet 文件 | 零依赖、Pandas 原生读写、后续可零成本迁移 DuckDB |
| 3 | LLM 调用点 | 仅策略决策 Agent | 成本可控、可复现、可审计；其他环节纯代码 |
| 4 | LLM 输入边界 | 只看代码预处理后的结构化结论 | 不让 LLM 碰原始数据计算，防止幻觉 |
| 5 | 运行模式 | Streamlit 交互驱动 | Phase 1 核心是验证分析质量，交互式调试最高效 |
| 6 | 分析单元 | 单票全面分析 | 其他场景（多票对比、板块分析）的原子单元 |
| 7 | 评分维度 | Phase 1 三维：技术面 + 基本面 + 资金面 | 三维已能验证核心链路，情绪面 Phase 2 补充 |
| 8 | 技术指标库 | pandas-ta | 130+ 指标开箱即用，Phase 1 用 MA/MACD/成交量比 |
| 9 | LLM 选型 | DeepSeek + Qwen，配置文件切换 | 共用 OpenAI 兼容协议 SDK，切换零成本 |
| 10 | 输出格式 | LLM 输出 JSON → 存 Parquet + 模板渲染报告 | 可存储、可对比、可回溯 |
| 11 | 数据源 | Phase 1 仅 Tushare | 减少集成复杂度，预留 adapter 接口 |

## 系统架构

```
Streamlit（输入股票代码/时间范围，点击"分析"）
    │
    ▼
┌─────────────────────────────────────────────────┐
│  LangGraph Pipeline                              │
│                                                   │
│  数据采集 Agent（纯代码）                         │
│    Tushare API → Pydantic 校验 → Parquet 落盘    │
│         │                                         │
│         ▼                                         │
│  行情分析 Agent（纯代码）                         │
│    pandas-ta 算指标 → 三维评分 → 结构化结论       │
│         │                                         │
│         ▼                                         │
│  策略决策 Agent（LLM 介入）                       │
│    结构化结论 → LLM 综合推理 → JSON 输出          │
│         │                                         │
│         ▼                                         │
│  报告推送 Agent（纯代码）                         │
│    JSON → Streamlit 模板渲染 + Parquet 存档       │
└─────────────────────────────────────────────────┘
```

### 各 Agent 职责与实现方式

| Agent | 实现方式 | 输入 | 输出 |
|---|---|---|---|
| **数据采集** | 纯代码（Tushare API + Pydantic） | 股票代码、时间范围 | 标准化 DataFrame（含 source/fetched_at 标注） |
| **行情分析** | 纯代码（pandas-ta + 评分函数） | 标准化 DataFrame | 三维评分 JSON（-2 ~ +2，含 reason/label） |
| **策略决策** | LLM（DeepSeek/Qwen） | 三维评分 JSON | 综合研判 JSON（结论 + 置信度 + 冲突识别 + 风险提示） |
| **报告推送** | 纯代码（Jinja 模板 + Streamlit） | 综合研判 JSON | 可读报告（Streamlit 展示 + Parquet 存档） |

## Phase 1 范围

### IN

- 单票全面分析（技术面 + 基本面 + 资金面）
- Tushare 数据采集（日线、财务、资金流）
- pandas-ta 技术指标计算（MA、MACD、成交量比）
- 三维评分系统（代码计算，-2 ~ +2）
- LLM 综合推理（仅策略决策环节）
- JSON 结构化输出 + Parquet 存储
- Streamlit 仪表盘（输入股票代码 → 查看报告）

### OUT

- 情绪面分析（Phase 2 加 AKShare 舆情数据时一起补）
- AKShare 数据源（Phase 2）
- 多票对比 / 板块分析
- 自动下单 / 券商 API
- 定时任务（等 Phase 1 验证通过后加）
- 美股 / 港股 / 全球市场

## Phase 2 预留接口

以下设计在 Phase 1 实现时需预留扩展点，避免 Phase 2 大改：

- **数据源 adapter 层**：数据采集 Agent 通过统一接口获取数据，Tushare 是第一个实现，AKShare 是第二个
- **评分维度扩展**：评分函数支持动态维度，Phase 2 加 `score_sentiment()` 即可
- **LLM provider 切换**：通过配置文件（`[llm] provider/model`）切换，不改代码
- **指标扩展**：pandas-ta 提供 130+ 指标，Phase 2 按"趋势/动量/波动率/成交量/形态"分组逐步引入
